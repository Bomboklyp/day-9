# Финальный performance audit

Дата: 24 ноября 2026, 17:54 МСК. Production-сборка Nuxt 4.6.4 / Nitro, Node v24.22.3, PostgreSQL 18.7, Windows, headless Chrome 157, Lighthouse 13.6.0.

## Метод

Четыре страницы, по три последовательных холодных запуска: 12 аудитов. Viewport 360×800, DPR 1, mobile, simulated throttling: CPU ×4, RTT 150 мс, 1638,4 Кбит/с. Во время замеров не выполнялись сборки, тесты и запись видео. Браузер отдельный, без пользовательских вкладок и расширений.

Перед каждым запуском очищены HTTP cache, localStorage, IndexedDB, cache storage и service workers. Для /requests восстановлена только учебная cookie оператора. Lighthouse проверяет фактический URL, поэтому вместо кабинета нельзя случайно измерить страницу входа. Cookie удалена из сохраняемых отчётов; после замеров сессия закрыта.

Сервер и БД локальные: эти цифры не включают задержку внешнего хостинга. Приведены медианы каждой метрики по трём запускам, а не лучший результат. CPU benchmark: 2801–3489.

## Принятые оптимизации

| Решение | Зачем |
| --- | --- |
| Prerender главной и отдельных статей; SSR поиска/кабинета | Содержательный первый HTML без ожидания клиентского API; приватные данные не попадают в статическую сборку |
| Локальный variable font, preload нужных наборов | Уменьшение шрифтовых файлов и стабильная геометрия текста |
| WebP для изображения с заданными размерами | Меньший transfer; размер известен до загрузки, нет скачка layout |
| Главное изображение загружается сразу; второстепенный виджет статьи отложен | LCP-изображение не задерживается lazy loading; ненужный стартовый JS откладывается |
| Взаимодействие вместо автоматического prefetch кабинета на landing | Приватные модули не скачиваются до намерения пользователя |
| Разделение chunks и сжатие public assets | Снижение передачи initial JS; общий размер проекта не выдается за размер первой загрузки |
| Debug отключён явно | Случайная переменная окружения DEBUG не включает отладочный режим релиза |

Текущие метрики — итог совместной работы решений. Этот аудит не изолирует вклад каждой строки таблицы.

## Повтор

```sh
npm ci
npm run db:init
npm run build
npm run perf -- release
```

Нужны PostgreSQL и .env либо DATABASE_URL, Chrome/Chromium. Путь к браузеру можно передать через CHROME_EXECUTABLE. Скрипт поднимает отдельный production-процесс, не использует вкладки пользователя и завершает его после аудита.

Данные: [release.json](docs/performance/release.json). Полные 12 отчётов: [lighthouse-release-reports.zip](docs/performance/lighthouse-release-reports.zip). SHA-256 app/server/shared, конфигурации и lockfile: `695cc08dabd73adfa374b3d2aca95306f19868eb506f387aef7e030438afbfed`.

Это лабораторные показатели. Полевые Core Web Vitals, INP, длительные сессии, сетевые задержки удалённого PostgreSQL и реальный production URL не измерены. После публикации нужен повтор внешнего аудита.
