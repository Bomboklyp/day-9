# ADR-003. Сервисы и репозитории в одном Nuxt-приложении

Статус: принято. Дата: 24.11.2026.

Контекст: SQL, HTTP и действия с заявкой были перемешаны. Проект использует одну базу и одно приложение; общей части для нескольких приложений пока нет.

Решение: HTTP handlers отвечают за параметры, валидацию и сессию; сервисы — за действия, права и транзакции; репозитории — за SQL. На клиенте отдельные адаптеры скрывают адреса API и типы ответа от визуальных компонентов. Nuxt Layers пока не используется.

Альтернатива: оставить SQL в handlers либо создать универсальную инфраструктуру, абстрактные репозитории и отдельный Layer для административных ролей.

Плюсы: изменение запроса к БД локализовано; HTTP-контракт можно менять через адаптер; транзакция явно охватывает заявку, комментарий и историю. Вызовы используют один переданный PoolClient.

Цена: простые справочники получают небольшой сервис-обёртку. Сервисы зависят от конкретных репозиториев, поэтому замена PostgreSQL потребует изменения data access. Это проще для текущего размера проекта, чем контейнер зависимостей и множество интерфейсов.

Nuxt Layers даст пользу при появлении второго приложения или общей административной части. Сейчас он добавил бы порядок наследования и переопределений без повторного использования.

Проверка: запрет прямого доступа HTTP handlers к repository/database, отсутствие циклов, реальные HTTP-тесты PostgreSQL и сохранение данных после перезапуска.
