# ADR-002. Один модуль правил переходов

Статус: принято. Дата: 24.11.2026.

Контекст: сервер знал разрешённые переходы, но обязательные причина и результат повторялись в форме. Назначение исполнителя дополнительно меняло статус внутри серверной операции.

Решение: хранить граф переходов, проверку обязательных полей, статус после назначения и возможности UI в `shared/utils/request-rules.ts`. Функции получают значения и возвращают результат или описание ошибки. В них нет Vue, Nitro, SQL и cookies. Сервер обязательно применяет правила самостоятельно внутри операции.

Альтернатива: две отдельные реализации на клиенте и сервере либо вызов API для получения каждого варианта формы.

Плюсы: одна логика для отображения и проверки; правила легко проверять обычными unit-тестами без Nuxt и базы данных.

Цена: браузер получает таблицу правил; изменение правил требует пересборки клиента. Это не защита само по себе: сервер остаётся источником разрешения действия. Активность исполнителя и доступ к конкретной записи зависят от БД и проверяются сервером.

Проверка: unit-тесты ролей, переходов, обязательных полей и назначения; HTTP и E2E-сценарии изменений заявки.
